# AgriSense AI — Administrator Provisioning Guide

## Overview

AgriSense AI strictly prohibits public administrator registration. Public user registration through the application always produces authenticated accounts with the **`farmer`** role.

Administrator accounts must be provisioned out-of-band using either:
1. **The Firebase Web Console** (Recommended for cloud management)
2. **The Trusted Backend Provisioning Script** (Recommended for local development & staging)

---

## Method 1: Firebase Web Console Workflow (Manual)

### Step 1: Create the User in Firebase Authentication
1. Navigate to the [Firebase Console](https://console.firebase.google.com/).
2. Select the active project: **`agrisense-ai-e5e42`**.
3. In the left navigation, click **Build** &rarr; **Authentication**.
4. Click the **Users** tab.
5. Click **Add user**.
6. Enter the administrator's **Email** and a secure **Password**.
7. Click **Add user**.
8. **Copy the User UID** generated by Firebase (e.g., `JHZZqyHxDqgHI7d0BvFlsuWXg4r2`).

### Step 2: Assign the Admin Role in Cloud Firestore
1. In the left navigation, click **Build** &rarr; **Firestore Database**.
2. Click on the **`users`** collection.
3. Locate the document matching the **User UID** copied from Step 1 (or click **Add document** with Document ID = UID).
4. Add or update the field:
   - Field name: `role`
   - Type: `string`
   - Value: `admin`
5. Ensure the document contains:
   ```json
   {
     "uid": "<USER_UID>",
     "email": "admin@yourdomain.com",
     "role": "admin",
     "updated_at": "2026-10-05T19:00:00Z"
   }
   ```
6. Click **Save**.

The user now holds full administrator authorization. Upon their next sign-in, the backend profile endpoint (`/api/v1/users/me`) will report `role: "admin"` and unlock the **ADMIN / SYSTEM &rarr; System Diagnostics** portal.

## Method 2: Trusted Backend Provisioning Script

The project includes a trusted server-side management script: [`backend/scripts/set_user_role.py`](file:///d:/AI%20project/backend/scripts/set_user_role.py).

### 1. List All Registered Users and Current Roles
```powershell
python backend/scripts/set_user_role.py --list
```
*Output:*
```text
=== Registered Users in Cloud Firestore ===
- UID: bMSsUbnABVbN5q65QKq2dIR6eo92 | Email: farmer.alpha@agrisense.dev | Role: farmer
- UID: JHZZqyHxDqgHI7d0BvFlsuWXg4r2 | Email: agronomist.audit@agrisense.dev | Role: admin
==========================================
```

### 2. Promote an Existing User by Email
```powershell
python backend/scripts/set_user_role.py --email admin@agrisense.dev --role admin
```

### 3. Promote a User by Firebase UID
```powershell
python backend/scripts/set_user_role.py --uid JHZZqyHxDqgHI7d0BvFlsuWXg4r2 --role admin
```

### 4. Demote an Admin to Farmer
```powershell
python backend/scripts/set_user_role.py --email user@agrisense.dev --role farmer
```

## Security Invariants

1. **Zero Trust on Frontend State**: The frontend role in `AuthContext` is strictly a client-side mirror of the authoritative backend response from `users/{uid}` in Cloud Firestore.
2. **Endpoint Protection**: All internal diagnostic routes (`/api/v1/system/diagnostics`) are protected by FastAPI's `require_admin` dependency. Requests from farmer accounts yield **`HTTP 403 Forbidden`**, and unauthenticated requests yield **`HTTP 401 Unauthorized`**.
3. **Public Registration Constraint**: The public registration payload never accepts or honors a `role` field. New signups are strictly defaulted to `role: "farmer"`.
4. **Deny-by-Default Fallback**: If a user document is missing in Firestore or lacks a `role` attribute, the backend and frontend safely default to `farmer`.
